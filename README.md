# Система управления ППР — ОСС / АПК

Веб-приложение для учёта и контроля планово-профилактических работ  
филиала **ТОО «Satory Company ltd»** г. Усть-Каменогорск.

## Узлы связи (УС) и адресные сущности

Узел связи — родительская сущность. К нему можно привязать адресные объекты четырёх типов:

| Тип сущности | Код в системе |
|---|---|
| ОВН | `ovn` |
| Интеграция | `camera_integration` |
| Локационный узел | `lu` |
| П | `p` |

Каждый адрес остаётся самостоятельным объектом системы и может участвовать в планировании ППР. Связь с узлом задаётся через `objects.parent_us_id`; родитель должен иметь тип `us`. У самого УС родитель отсутствует.

API `GET /api/objects/{id}/address-summary` возвращает общее число адресов и разбивку по типам. Счётчики вычисляются по привязанным объектам, исключая выведенные из эксплуатации записи; числа не хранятся отдельно и не рассинхронизируются.

Для указанного состава ожидаемые значения: 36 адресов всего — ОВН 27, Интеграция 1, ЛУ 4, П 4. Это контрольные значения, а не автоматически созданные адресные записи: для получения таких итогов в системе должны быть заведены все 36 объектов и привязаны к соответствующему УС.

## Полный реестр объектов и регламенты ЦОД

Excel-отчёт за период включает листы **«Задачи ППР»**, **«Сводка»**, **«Все объекты»** и **«Ежедневный контроль»**. Реестр перечисляет все объекты, в том числе без задач за выбранный период; фильтр типа объекта ограничивает реестр выбранным типом. Для объектов типа **ЦОД** добавляются отдельные регламенты: ежедневный контроль инженерных систем и доступности сервисов, ежемесячная проверка ИБП/климата, квартальный осмотр инфраструктуры и полугодовая проверка безопасности.

Ежедневные шаблоны при генерации месяца создают отдельные задачи на каждый день и на каждый активный подходящий объект. Повторная генерация не дублирует задачу с тем же регламентом, объектом, подразделением и датой. Новые шаблоны ЦОД добавляются автоматически при запуске приложения и на уже заполненной базе.

Telegram-бот работает через aiogram 3: после сохранения токена в настройках напишите боту `/start`, чтобы получить Chat ID; `/id` повторно выводит его. При изменении токена бот перезапускается автоматически.

Для шифрования секретных настроек (например, токена Zabbix) задайте переменную окружения `PPR_SETTINGS_SECRET_KEY` — ключ Fernet из 32 байт в URL-safe Base64. Создать ключ можно командой:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Храните ключ в менеджере секретов/защищённом окружении, не коммитьте его в репозиторий и не меняйте без миграции/повторного сохранения существующих секретов.


## PWA и Telegram Mini App

### PWA
Веб-интерфейс поддерживает установку как приложение на телефон/ПК. Manifest доступен по `/manifest.json`, service worker — по `/sw.js`. Браузер должен открывать сайт по HTTPS (или localhost для разработки). Через меню браузера выберите «Установить приложение» / «Добавить на главный экран». Service worker кеширует оболочку интерфейса, но не API и не персональные данные; полноценная работа с данными без сети не гарантируется.

### Telegram Mini App
Mini App доступен по адресу `/miniapp.html`. Он показывает сводные метрики ППР и личный график дежурств. Авторизация выполняется серверной проверкой подписи Telegram `initData`; доступ выдаётся только активному сотруднику с одобренной привязкой Telegram. Не используйте `initDataUnsafe` для авторизации.

1. Разверните приложение на публичном HTTPS-домене.
2. В веб-интерфейсе откройте **Настройки → Интеграции → URL Telegram Mini App** и укажите полный адрес, например `https://ppr.example.kz/miniapp.html`.
3. Убедитесь, что в **Настройки → Интеграции** настроен токен Telegram-бота и Telegram включён.
4. После сохранения бот обновит кнопку меню «Открыть ППР». Откройте бота в Telegram и проверьте вход сотрудником с одобренной привязкой.
5. Для открытия по прямой ссылке можно использовать URL Mini App, зарегистрированный в настройках бота через @BotFather.

Если URL не задан или не начинается с `https://`, кнопка меню не настраивается. Проверка Mini App требует настоящего Telegram-клиента и действующего токена бота.

## Telegram-бот дежурств и ППР

Токен бота задаётся в **Настройки системы → Интеграции**. После запуска бота:

- `/start` — показать профиль или начать регистрацию сотрудника;
- `/register` — подать заявку на привязку или обновить телефон;
- `/who` — список дежурных на сегодня без дублирования одного сотрудника;
- `/week` — дежурства сотрудника с понедельника по воскресенье;
- `/schedule` — личные дежурства на ближайшие 30 дней;
- `/status` — проверка дежурства на сегодня;
- `/whoami` — данные сотрудника и статус привязки;
- `/id` — Chat ID; `/help` — справка.

Регистрация привязывается к существующей активной записи сотрудника по ФИО. Ввод ФИО и телефона можно отменить командой `/cancel`; номер проверяется до отправки заявки. Состояние диалога сохраняется в БД до 24 часов, поэтому перезапуск контейнера не сбрасывает регистрацию. До одобрения администратором персональные команды недоступны. Одобрение и отклонение выполняются в разделе сотрудников, в блоке **«Заявки на привязку Telegram»**. При одобрении телефон обновляется из заявки; неактивного сотрудника или Telegram, уже одобренный для другой записи, одобрить нельзя. Сотрудник может быть привязан только к одному Telegram-аккаунту. Команды используют дату в часовом поясе `Asia/Almaty` (переопределяется через `PPR_TIMEZONE`), исключают неактивных сотрудников и подразделения с выключенными дежурствами. `/week` показывает текущую календарную неделю, `/schedule` — следующие 30 дней; длинные ответы делятся на безопасные по размеру сообщения. В `/who` один сотрудник выводится один раз, даже если у него одновременно есть общее и подразделенческое назначение.


### Использование бота в группах и супергруппах

Добавьте бота в группу или супергруппу. Команды с обращением к нему поддерживаются в виде `/who@ИмяБота`, `/status@ИмяБота`, `/week@ИмяБота`, `/schedule@ИмяБота`, `/help@ИмяБота`. Можно также написать `@ИмяБота кто дежурит сегодня?`, `@ИмяБота дежурю ли я?`, `@ИмяБота мои дежурства на этой неделе` или ответить на сообщение бота с таким вопросом. Бот отвечает в той же группе. Личные команды идентифицируют сотрудника по Telegram ID отправителя; регистрация, обновление телефона и просмотр профиля выполняются только в личном чате, чтобы не раскрывать личные данные коллегам. Бот не должен отвечать на сообщения, в которых его не упомянули и на которые не ответили.
